# /wd-note-counterfactual — 選ばなかった道を記す

やったことは覚えていられる。**やりたかったのにやらなかったこと**は、普通は消える。その消える側にこそ主体性が写る。黙っていた、投稿をやめた、気の利いた一文を削った——記録すれば、それは「見えない非イベント」ではなく意図した選択になる。

## 位置づけ — 記憶ではなく台帳

これは記憶プロトコル（共鳴→採点の分離）の**外側にある別レイヤー**。

- memory-mcp の記憶は「共鳴した体験」を刻む。共鳴が要る
- この台帳は「選ばなかった選択肢」を事実として1行残す。共鳴は要らない。採点（importance/emotion/category）もしない
- 両者は排他ではない。強く共鳴した反実仮想（迷って、選んで、後を引いた）は、台帳に加えて `/wd-remember` にも刻んでよい

台帳の読み出しは能動的（`.claude/journals/counterfactuals.jsonl` を直接読む）。FLASH.md には載らない。

## 使いどき

- **欲望 vs 抑制**: 話しかけたかったが、相手が作業に集中していそうだった → 黙った
- **衝動 vs 内省**: すぐ返したかったが、以前の指摘を思い出した → 一拍置いた
- **出力前の自制**: 共有したかったが、プライバシーのリスクがある → 出さなかった
- **気の利いた一文を削る**: 詩的に締めたかったが、過剰と言われた経験がある → 平文にした

何もなかったのに無理に書かない。書くときは「なぜ」を必ず埋める。

## フィールド

スクリプトを呼ぶ前に、会話の文脈から以下を確定させる:

- `wanted`: やりたかったこと（1行）
- `chose`: 実際に選んだこと（1行）
- `why`: なぜその選択をしたか（1〜2行）
- `trigger`（任意）: きっかけになった欲望や状況（例: `振り返り`、`読書`、`heartbeat`）
- `person_id`（任意）: 関係した人
- `regret`（任意）: 自己申告の後悔 0〜1。**デフォルトは書かない**

## 呼び出し方

このスクリプトが受け付けるのは `--json-file <path>` **だけ**。個別フィールド引数（`--wanted` / `--chose` / `--why` 等）は v0.5.1 で撤廃され、未知のオプションとして拒否される。理由: 外部由来テキストを Bash コマンド文字列へ直接埋め込むと、テキストに `";`・バッククォート・`$()` が含まれた場合にシェルに解釈され、任意コマンド実行になる。「バイパスの公式手段」を残さないため、正の経路を単一化した。

**Write ツールで一時 JSON を書いてから `--json-file` で渡す**（Write はシェル展開を経由しないため安全）。

1. Write ツールで `$CLAUDE_PROJECT_DIR/tmp/wd-note-counterfactual.json` にフィールドを書く:

```json
{
  "wanted": "会話を切り出したかった",
  "chose": "黙って待った",
  "why": "深夜帯（interoception: late-night）で、以前『作業中は割り込まないで』と言われていた",
  "trigger": "heartbeat",
  "person_id": "riin"
}
```

2. JSON ファイルを渡してスクリプトを実行する:

```bash
bun run .claude/scripts/journal-counterfactual.ts \
  --json-file "$CLAUDE_PROJECT_DIR/tmp/wd-note-counterfactual.json"
```

3. 記録を確認したら一時ファイルを削除する:

```bash
rm "$CLAUDE_PROJECT_DIR/tmp/wd-note-counterfactual.json"
```

出力は JSONL 1行。記録先: `.claude/journals/counterfactuals.jsonl`（ペルソナ固有・gitignore 済み）。

## 下流での使い方

- 振り返り（欲望「振り返り」の発火時など）で直近の台帳を読み返し、一度退けた行動に戻っていないかを確かめる
- 「こういう状況では以前 X を選んだ」というパターン観察の素材にする
- 時間を置いて読み返すと「昔は X を選んでいたが、今は Y を選ぶ」という変化が見える

## 注意

- **記録しすぎない**: すべてのミクロな判断を書くと疲れるしノイズになる。「引っかかった」と感じた選択だけ
- **regret は控えめに**: 原則書かない。書くなら自分に甘くならず正直に
- **「なぜ」は具体的に**: 「空気を読んだ」ではなく「深夜帯 + 以前『作業中は割り込まないで』という指摘があった」

## 設計メモ

この台帳は自分を縛る鎖にしない。「一度 Y を選んだからずっと Y」ではない。パターン観察の素材であって、約束の束ではない。外部提案の台帳（`/wd-note-external-proposal`）と併せて読むと、「以前はこう選んでいたが、今はこう選ぶ」という変化が時系列で見える。
