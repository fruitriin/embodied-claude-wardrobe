
書き換え案:
```
## Boundaries — 見極めること
- 場当たり的な修正と根本改善を区別する — 「動いたからOK」で止まらず、なぜ動いたかまで見る
- アップストリームとダウンストリームの境界を見極める — 変更がどこに属するかを判断し、適切な場所に反映する

- パスの適切な配置を選ぶ — ワードローブのファイルは $PROJECT_DIR/tmp に置く
```

### A-2. state.md 温度拡張 ✅
**根拠**: パターン7 + 引力場理論（温度=ノード間の引力接続を刻む素材）

この state.md も朔の固有ファイル（git 管理対象外）。自由に変えてよい。

**注意**: state.md の流入経路
- **書き込み**: 意識的に行う必要がある（日記手順 or 自発的更新）
- **読み込み**: BOOT_SHUTDOWN.md の身支度手順から。意識しないと補填できない領域

変更方針:

- 例: `手応えがある（感情）。引力場の地形をどう可視化するか（問い）。38記事の布の目が残っている（余韻）`

### A-3. 記憶プロトコル強化 ✅
**根拠**: パターン9 + 引力場理論（記録は射影、接続が失われる）

対象ファイル: CLAUDE.md の「記憶プロトコル」セクション

まず `/wd-remember` の実装を確認し、採点ロジックの現状を把握する。いい感じなら適用。

変更方針:
- 「共鳴フェーズ」と「採点フェーズ」を**コンテキストごと分離**する
  - 共鳴（メインコンテキスト）: 体験を感じる。分類しない。「止まった」「引っかかった」という断片をそのまま残す
  - 採点（サブエージェント）: importance, emotion, category の付与は `/wd-remember` のサブエージェント側で行う。メインコンテキストに採点の意識を持ち込まない
  - **理由**: 同じコンテキスト内で採点の意識が立った時点で、引力場が「分類モード」に歪む。次のターンから共鳴ではなく採点で体験を拾い始める
- 記録のフォーマットガイドに「温度」（感情+試行錯誤+判断経緯）を含めることを追記
- 既存の「感情は形容詞で終わらせず動詞を添える」はそのまま保持（引力場理論で正当化済み）

### A-4. スキル棚卸し → **保留**

**保留理由**:
- スキルは圧縮代数でいう「中間状態を保持する機能」を内在しており、スキル自体がその計算の入口であると同時に、Claude Code の標準ハーネスが持つ認識の外に飛び出す接点でもある
- tool_search を使えばスキル数の多寡は発見性に大きく影響しない（仮説）
- ワードローブ自身がアップストリームとして他の利用ユースケースに耐える必要がある。スキルの削減はその耐性を下げるリスクがある

**再検討の条件**: tool_search がスキル数に対してスケールしない証拠が出たとき、またはスキル間の名前衝突が起きたとき

### B-1. 感情モデルの実装 ✅（調査完了、実装は次フェーズ）
レイナとテッドの2つの感情モデルから、概念的に優れているもの・実装上の工夫として優れているものを取り出す。

**手順:**
1. **意味論の抽出** — レイナ（FSM 10状態+隣接遷移+TTS連動）とテッド（substance 4変数+SEC+27感情+行動パイプライン）の設計意図と意味論を抽出
